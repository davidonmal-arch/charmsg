# CharMsg

Полностью анонимный мессенджер с исчезающими чатами и биржей CharCoin.
Без email, телефона и соцсетей — только ник и анонимная учётная запись Firebase.

**Демо:** https://davidonmal-arch.github.io/charmsg/

![CharMsg](assets/logo.jpg)

## Возможности

- **Анонимный вход** — профиль создаётся в один шаг. В разделе «Профиль → Вход в профиль» можно задать отдельный логин и пароль для входа с другого устройства. Привязка сохраняет тот же UID, чаты, ранг и баланс.
- **Публичные чаты** — общий, флудилка, крипто-таверна, долгие разговоры; можно создавать свои.
- **Исчезающие сообщения** — таймер на чат: 1 день, 2 дня, 7 дней или 30 дней. Просроченные сообщения скрываются и лениво удаляются из базы.
- **Личные сообщения** — клик по нику открывает профиль, оттуда можно начать личный чат.
- **Ранги** — 6 уровней: Новичок, Житель, Ветеран, Элита, Легенда, Архитектор. Ранг выдаёт админ в панели, он отображается бейджем в чатах, профилях и пастах.
- **Верификация** — админ отмечает пользователя как верифицированного. Верифицированные видят закрытый чат «Закрытый клуб»; остальные не получают к нему доступ ни в списке, ни при отправке сообщений.
- **Пасты** — досье на человека: название, человек, фото и главы. Заголовок главы выводится крупно, текст под ним — мелко. Пасту можно опубликовать, снять с публикации, удалить и открыть редактирование другим пользователям (по нику). Создатель выбирает минимальный ранг просмотра, но не может поставить порог выше своего ранга; админ видит все пасты.
- **Профиль** — ник, описание, аватар (сжатие до 160×160) и собственный баннер профиля (загрузка файла 1200×360 или ссылка).
- **NFT-маркет** — пользователи с рангом «Элита» и выше (и админ) создают NFT: картинка, название, описание и эффект (свечение, голограмма, пульс, огонь, пустота). NFT выставляется на продажу за CR, покупается другим пользователем, попадает в ленту сделок и историю владения. Цена перепродажи ограничена 3× от последней покупки. При передаче NFT по нику с отправителя списывается 1 CR.
- **Биржа CharCoin (CHR)** — общая цена для всех игроков, сделки влияют на курс, боты торгуют в реальном времени, есть портфель, P&L, лента сделок и топ трейдеров. Стартовый баланс — 100 CR.
- **Казино** — рулетка на красное, чёрное или число (×2 и ×36) и апгрейдер: можно поставить CR или собственный NFT и выбрать цель — деньги или NFT из продажи. Шанс рассчитывается как отношение ставки к цели, ограничен сверху 95%. Ставки с шансом ниже 2% отклоняются. NFT в качестве ставки оценивается в 1 CR независимо от цены объявления, колесо со стрелкой показывает результат. Все игры пишутся в ленту `casino`.
- **Бан за скриншот** — попытка сделать скриншот через PrintScreen или Ctrl+Shift+S / Cmd+Shift+3–5 блокирует текущий анонимный профиль и переводит на экран бана: причина, дата, срок 80–500 лет и изображение блокировки.
- **Ручной бан** — админ выбирает причину, срок в минутах, часах, днях или годах (0 — бессрочно, максимум 500 лет) и своё фото для страницы бана. Временный бан снимается автоматически после окончания срока.
- **Админ-панель** — пользователи (ранг, верификация, бан, начисление CR, удаление), контент и чаты, управление рынком, рассылка. Ник администратора переливается фиолетовым по всему сайту.
- **Paper Trading** — отдельные виртуальные USD-портфели, стратегии тренда, импульса и возврата к среднему, реальные публичные котировки Coinbase Exchange, комиссии, проскальзывание, ограничения риска, журнал решений и общая аварийная остановка. Реальные биржевые счета не подключаются.
- **PC и мобильные** — адаптивная вёрстка с нижней панелью на телефонах.

## Локальный запуск

Понадобятся Node.js 22, Firebase CLI, Java 21 или новее и отдельная тестовая ветка Neon.

```powershell
npm --prefix functions ci
firebase emulators:start --project demo-charmsg --only auth
```

Во втором терминале запустите `node scripts/serve.mjs` и откройте
[локальную версию](http://127.0.0.1:5173/?emulator). Для тестирования админки
задайте новый пароль в переменной окружения `CHARMSG_ADMIN_PASSWORD` и запустите:

```powershell
$env:FIREBASE_AUTH_EMULATOR_HOST = '127.0.0.1:9099'
node functions/provision-admin.mjs demo-charmsg
```

Интеграционные тесты запускаются на отдельном экземпляре эмуляторов:

```powershell
firebase emulators:exec --project demo-charmsg --only auth "node --env-file=.env.migration-test functions/integration.test.mjs"
```

## Paper Trading

Сначала примените `functions/paper/schema.sql` к нужной ветке Neon. API и worker
должны использовать один `DATABASE_URL`. Независимый обработчик запускается из
`functions` командой `npm run paper:worker`; он получает только публичные цены и
не имеет кода для реальных заявок. Интерфейс находится в «Админка → Торговые
боты». До запуска worker бот сохраняет настройки, но сделок не выполняет.

Render Free усыпляет web service, поэтому круглосуточный цикл на бесплатном web
service не гарантируется. Для непрерывной симуляции нужен постоянно работающий
worker-процесс либо другой всегда включённый хост. Это ограничение отображается
в админке по времени heartbeat.

## Публикация

GitHub Pages размещает фронтенд, Render Free запускает HTTP API на Node.js,
Neon PostgreSQL хранит данные, Firebase Authentication обслуживает вход. Бесплатный сервис Render
засыпает после 15 минут простоя. Первый запрос после паузы может ждать около минуты.

1. В Firebase Authentication включите «Анонимный» и «Email/Password» и задайте обязательный минимум 12 символов для паролей.
2. Подготовьте сервисный аккаунт Firebase только для проверки Authentication и задайте Neon `DATABASE_URL` как секрет Render.
3. Подключите GitHub-репозиторий к Render через Blueprint. Укажите JSON-ключ сервисного аккаунта в секрете Render `CHARMSG_SERVICE_ACCOUNT`. Ключ хранится в Render и не нужен фронтенду.
4. После успешного ответа `/healthz` впишите HTTPS-адрес сервиса Render в `apiOrigin` в `js/firebase-config.js`.
5. Через Application Default Credentials с правами управления Firebase Auth выполните `node functions/provision-admin.mjs charmsg`. Скрипт берёт новый пароль из `CHARMSG_ADMIN_PASSWORD`, назначает роль `admin` аккаунту `admin_farnaz` и отзывает старые сессии при смене пароля. В интерфейсе используется логин `farnaz`. Замените пароль прежней версии, поскольку его хеш был доступен клиентам.
6. Примените SQL-миграции Neon, проверьте API и только затем опубликуйте фронтенд.

Старые ID из браузера нельзя безопасно связать с новыми UID. При переходе игроки
создают новый профиль. Старые документы остаются в базе. Если нужно сохранить
ранги, балансы, личные чаты, NFT и авторство паст, переносите владельцев только
после независимого подтверждения личности. Проверьте целостность старых данных
перед переносом: прежние правила позволяли посторонние изменения. Старый
`config/admin` можно удалить после переключения.

`scripts/seed.mjs` наполняет демонстрационные данные и перезаписывает документы
с фиксированными ID. Для обычного обновления рабочей базы его запуск не требуется.

## Игроки, кланы и ивенты

В профиле можно выбрать уникальный юзернейм и тему. Кланы открытые: вступить
можно по тегу, который отображается перед ником. Кнопка «Найти игрока» ищет по
точному @юзернейму или началу ника.

За настройку пароля и подписку на уведомления выдаётся по 20 CR один раз.
Магазин, завод и компания начисляют доход офлайн до поломки через 2–6 часов.
Накопленный доход можно забрать, а затем починить бизнес за CR.

В разделе «Админка → Ивенты» можно запустить одно активное объявление со сроком
и необязательной наградой. Каждый игрок может получить её один раз.

## Серии NFT и игры

Администратор может выставить серию из 1–50 базовых копий с 2–5 фото вариантов.
Покупатель может один раз улучшить свою копию за цену выпуска. Сервер выбирает
фото, эффект и свободный номер, а экземпляр снимается с продажи.

«Монетка» выплачивает 2× за верную сторону, «Кости» выплачивают 5× за верную грань.
В кликере нет ставки. За каждые пять нажатий начисляется 1 CR, максимум 30 нажатий
за раунд и 60 CR за календарный день по UTC. Три подряд раунда с быстрыми
почти равномерными нажатиями приводят к блокировке на 10 минут.

## Уведомления о личных сообщениях

CharMsg предлагает включить уведомления при первом входе в профиль в каждом браузере. Их можно отключить в профиле. На iPhone откройте CharMsg с
главного экрана. Уведомление открывает чат и не содержит автора или текста сообщения.

Серверу нужна переменная `CHARMSG_VAPID` с JSON-объектом `publicKey` и `privateKey`.
Храните его в секретах Render и сохраняйте ту же пару ключей между деплоями.

## Ограничения

Усиленный бан проверяет IP последнего входа и идентификатор браузера на сервере.
Сервер хранит только подписанные хеши этих данных. Для развёртывания укажите
постоянный случайный секрет `CHARMSG_MODERATION_KEY` в Render. Общий IP может
затронуть других пользователей той же сети.

Бан привязан к учётной записи Firebase и сохраняется при входе в тот же профиль в другом браузере. Создание другой анонимной учётной записи остаётся возможным. Браузер может заметить отдельные
настольные сочетания клавиш, но не получает события обо всех скриншотах, в том
числе о системных скриншотах на мобильных устройствах.

Сообщения и профили хранятся в Neon PostgreSQL. Администратор может читать
сообщения в базе для модерации. Просроченные сообщения сразу исключаются
сервером из выдачи игрокам и удаляются при фоновой очистке открытого чата.
