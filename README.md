# CharMsg

Полностью анонимный мессенджер с исчезающими чатами и биржей CharCoin.
Без email, телефона и соцсетей — только ник и анонимный ID устройства.

**Демо:** https://davidonmal-arch.github.io/charmsg/

![CharMsg](assets/logo.jpg)

## Возможности

- **Анонимный вход** — профиль создаётся в один шаг, идентичность хранится в `localStorage`.
- **Публичные чаты** — общий, флудилка, крипто-таверна, долгие разговоры; можно создавать свои.
- **Исчезающие сообщения** — таймер на чат: 1 день, 2 дня, 7 дней или 30 дней. Просроченные сообщения скрываются и лениво удаляются из Firestore.
- **Личные сообщения** — клик по нику открывает профиль, оттуда можно начать личный чат.
- **Профиль** — ник, описание, аватар (загрузка файла со сжатием до 160×160 или ссылка).
- **Биржа CharCoin (CHR)** — общая цена для всех игроков, сделки влияют на курс, боты торгуют в реальном времени, есть портфель, P&L, лента сделок и топ трейдеров. Стартовый баланс — 100 CR.
- **Админ-панель** — пользователи (бан, начисление CR, удаление), контент и чаты, управление рынком, рассылка. Ник администратора переливается фиолетовым по всему сайту.
- **PC и мобильные** — адаптивная вёрстка с нижней панелью на телефонах.

## Локальный запуск

```powershell
cd charmsg
node scripts/serve.mjs
# http://localhost:5173
```

Любой статический сервер подойдёт: приложение не требует сборки.

## Firestore

```powershell
firebase deploy --only firestore:rules --project charmsg
node scripts/seed.mjs   # нужен FIREBASE_TOKEN и SEED_ADMIN_PASSWORD
```

Конфигурация Firebase — `js/firebase-config.js` (публичные ключи веб-приложения).
Правила — `firestore.rules`; документ `config/admin` доступен только на чтение клиентам,
запись выполняется скриптом наполнения.

### Администратор

- Логин: `farnaz`
- Пароль задаётся владельцем и в репозитории не хранится.
- В Firestore лежит только SHA-256 хеш (`config/admin`), сессия живёт 12 часов.
- Вход: иконка замка в шапке или вкладка «Профиль» → «Войти как администратор».

## Ограничения демо

Проект задуман как анонимный и не использует Firebase Auth: личность — случайный ID
устройства, а правила Firestore разрешают анонимные чтение и запись с валидацией полей.
Это удобно для демо, но не даёт криптографической защиты от подмены профиля или
админ-действий. Для продакшена нужен Firebase Auth (анонимный вход) и правила на
`request.auth.uid`, а админ-действия — через Cloud Functions/Admin SDK.

Сообщения и профили хранятся в Google Firestore. Не публикуйте личные данные.
